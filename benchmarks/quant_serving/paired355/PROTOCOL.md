# Can two clients finish sooner on one 355B model?

This opt-in evaluation requires a completed single-GB10 GLM-4.5 capacity run with its four exact repeat pairs and independently matched tokenizer inputs. It is not a second model copy or a larger KV allocation: `--parallel 2 --ctx-size 4096 --no-kv-unified` partitions the existing context into two 2048-token slots. We re-check whole-shard hashes, the native runtime and CUDA layer receipt, the original RAM/disk admission, idle GPU and the physical guard. Never lower a reserve or evict another job. Both arms run on the *same* two-slot server; the one-slot reference is used for outputs, never as the timed serial arm.

Two independent server processes, each with a warmup in each slot. Each launch measures two paired prompts of the same length (128 and 1024), two serial/overlapped arm orders, with the lead prompt reversed in the second round. The four independent precomputed input digests and EOG IDs must match. Each request has cold prompt KV, deterministic greedy sampling and a 16-token fixed cap using the same EOG mask as capacity. There are 16 timed waves, 32 completions and 4 excluded warmups in total. Process startup, CPU metrics requests outside each wave, and weight hashing are not timed. Common time origin at simultaneous eligibility; only the serial arm withholds the second request until the first completes. Both arms expose first-completion time and time to the last response. Outputs and scheduler differences are kept even if they invalidate a recommendation.

Native `/metrics` snapshots before and after each wave must be idle and adjacent. Deltas must account for exactly all input/output tokens. Recover the cumulative integer busy-slot sum only if a *unique* numerator fits the pinned server's rounded six-significant-digit average and its decode-call counter. Busy slots are processing states sampled at native `llama_decode`, not proof of exact per-kernel token packing. Overlapping client intervals alone are not a throughput or occupancy result.

Predeclared, separately reported gates: every matched pair must improve end-to-end burst makespan by at least 5%, delay the first completed response by at most 10%, preserve complete token sequences across all arms and versus the accepted baseline, and show actual joint server occupancy for the simultaneous arm. Two lengths × two orderings × two launches, no post-hoc selection. A measured loss is retained. No default change, natural-language accuracy or broad serving SLA claim.

`mini_native.py` exercises the actual pinned HTTP server on a tiny randomly initialized single-layer CPU-only fixture. Its timings are never pooled with the GLM experiment. It intentionally permits overlap without verified backend occupancy: that case is a negative finding, not a harness failure.
